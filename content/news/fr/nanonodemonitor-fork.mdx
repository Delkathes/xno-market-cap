# Le fork nanoNodeMonitor : thème moderne, PHP 8.5 et vérification de version RsNano

nanoNodeMonitor, le tableau de bord web auto-hébergé pour la santé des nœuds Nano, reçoit à nouveau une vraie maintenance. Le fork maintenu par Gigaion a livré deux mises à jour en juin : une passe de modernisation le 10 juin et la v1.10.0 le 23 juin, qui corrige la bannière de version RsNano.

L'outil est ancien et éprouvé : du PHP côté serveur qui parle à votre nœud via RPC et affiche son statut, sa synchronisation, ses pairs et son vote sur une simple page web. Comme tout tourne côté serveur, l'interface RPC du nœud n'est jamais exposée au public. Le projet d'origine a été archivé, et le fork de Gigaion reprend le flambeau, modernisé pour PHP 8.1 à 8.5 avec un durcissement de la couche cache et du rendu des templates.

## La mise à jour du 10 juin

Le lot de modernisation couvre les bases qui gardent un outil auto-hébergé utilisable :

- Un nouveau thème moderne, en plus des thèmes clair, sombre et Banano existants.
- La compatibilité avec PHP 8.5.
- La génération de QR codes en local, qui supprime une dépendance tierce et les appels externes associés.
- GitHub Container Registry (GHCR) comme source d'images préférée, Docker Hub conservé en secours.
- Une logique de migration de config.php pour simplifier les mises à jour. Les conteneurs Docker migrent la config au démarrage ; les installations manuelles lancent un script qui sauvegarde l'ancienne config, reprend les réglages et écrit un fichier propre avec un marqueur de version.

## v1.10.0 : le correctif de la bannière RsNano

La sortie du 23 juin est petite mais utile. La vérification de version de nanoNodeMonitor ne comprenait que le nœud C++, si bien que les opérateurs sous RsNano, la réécriture en Rust couverte ici en juin, voyaient un avertissement « version serveur obsolète » même sur la dernière version. La v1.10.0 vérifie correctement les versions RsNano : plus de fausse alerte sur les builds à jour, et la bannière suggère désormais une mise à niveau quand une nouvelle version de RsNano sort.

Gigaion crédite badsyntax_ pour la correction suggérée.

## La note de transparence

L'annonce comme le README indiquent clairement que le développement assisté par IA a été utilisé durant ce cycle, et invitent aux revues de sécurité et à l'examen par la communauté. Pour un outil qui se branche sur le port RPC de votre nœud, c'est la bonne posture : lisez le code, signalez les problèmes, jugez par vous-même. L'objectif affiché est de garder le fork activement maintenu plutôt que de le laisser stagner.

## Essayez-le

Le déploiement est pensé Docker d'abord, et l'image GHCR est la source recommandée :

<Terminal title="tirer l'image GHCR">
docker pull ghcr.io/gigaionllc/nanonodemonitor:latest
</Terminal>

Les installations manuelles restent possibles : clonez le dépôt, copiez config.sample.php vers config.php, pointez vers votre nœud. Le README couvre aussi le script de migration pour les installations existantes, et les configs contenant de la logique PHP personnalisée sont détectées et jamais réécrites.

Si vous faites tourner un nœud Nano ou Banano, ce tableau de bord vaut le détour. Le fork de l'archivé [NanoTools/nanoNodeMonitor](https://github.com/NanoTools/nanoNodeMonitor) est vivant, maintenu, et mérite un coup d'œil.
