# RsNano V3.0 : une seule base de code, deux monnaies

[RsNano](https://github.com/rsnano-node/rsnano-node) est la réécriture en Rust du nœud Nano, et le développeur gschauwecker a publié sa plus grosse version à ce jour. V3.0 transforme le projet : ce n'est plus seulement un nœud Nano, mais un nœud pour deux chaînes. La même base de code compile désormais pour Nano ou pour Banano, la monnaie étant choisie au moment de la compilation. La vedette de cette version, c'est la prise en charge de Banano au même niveau que celle de Nano.

## Une base de code, deux monnaies

La prise en charge de Banano est complète, pas un bricolage. Une option de compilation `banano` sélectionne la monnaie à la compilation. Le dépôt embarque les poids de représentants et les constantes monétaires des deux réseaux, et compiler pour Banano produit un binaire dédié, `rsban`. Si vous interrogez le RPC version sur une version compilée pour Banano, il répond « RsBan ». Pas de fork séparé à maintenir, pas de deuxième base de code qui peut diverger.

Pour les opérateurs Banano, c'est important : le réseau dispose enfin d'une alternative indépendante au nœud C++, écrite en Rust.

## Images Docker officielles

RsNano fournit désormais des images Docker officielles, publiées automatiquement à chaque push via GitHub Actions. Elles sont basées sur Alpine pour rester légères, et les compilations passent par cargo-chef pour des couches mises en cache efficacement. Il y a une image distincte pour chaque monnaie :

<Terminal title="lancer les images officielles">
# Nano
docker run -p 7075:7075 -v ~/Nano:/home/nanocurrency/Nano rsnano/rsnano:V3.0 node run

# Banano
docker run -p 7075:7075 -v ~/Banano:/home/bananocurrency/Banano rsnano/rsban:V3.0 node run
</Terminal>

Les deux images exposent le même port, 7075. Si vous voulez faire tourner les deux chaînes sur une seule machine, adaptez le côté hôte du mapping `-p`.

## L'interface Insight, sérieusement améliorée

La GUI de supervision a reçu une grosse mise à jour. Nouvelles vues : visualisation du score des pairs, élections actives (AEC) avec le détail par compartiment, une vue détaillée des élections et une vue Bootstrap complète qui montre les comptes bloqués, en téléchargement et priorisés, avec filtres et vérification de cohérence. S'ajoute le filtrage du journal des messages par direction et par type.

## Moteur de bootstrap réécrit

Le sous-système de synchronisation du registre a été retravaillé en profondeur plutôt que rafistolé. Le trafic réseau en direct est désormais ignoré pendant le bootstrap, pour que les blocs entrants ne perturbent pas la synchronisation. Les priorités et tailles de pull ont été ajustées pour correspondre au comportement du `nano_node` officiel, et l'annonce liste des corrections pour les blocages de synchronisation, les gels et les fuites de block-handoff. Ces bugs sont difficiles à reproduire ; les correctifs méritent donc d'être testés en conditions réelles.

## Le reste du journal des modifications

- Un nouveau réglage réseau `handshake_timeout`, avec nettoyage centralisé des canaux inactifs.
- Des valeurs par défaut LMDB modifiées pour la performance : `nosync_unsafe` et `NO_READAHEAD`.

<Callout type="warning" title="Un compromis à connaître">
	`nosync_unsafe` échange de la durabilité contre du débit : LMDB saute la synchronisation des données sur le disque à chaque commit. Sans problème pour la plupart des nœuds, moins bien sur du matériel peu fiable.
</Callout>

- Des vérifications de cohérence du registre au démarrage.
- De nouveaux outils CLI : infos sur le poids des représentants et un outil de comparaison du registre.
- Passage à l'édition 2024 de Rust.

V3.0 est une version substantielle : une deuxième monnaie, un chemin de synchronisation reconstruit et une distribution soignée. Les opérateurs de nœuds devraient tester le chemin de bootstrap sur un nœud de préproduction avant de mettre à jour leur mainnet. Les opérateurs Banano ont enfin le choix.
